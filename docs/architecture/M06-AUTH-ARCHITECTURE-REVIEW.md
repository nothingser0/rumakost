# Review arsitektur autentikasi M06

Tanggal: 2026-11-03  
Status: Owner memilih Better Auth self-hosted pada Neon PostgreSQL untuk implementasi M06; migrasi runtime belum dikerjakan.

## Masalah yang harus diselesaikan

M06-BE-18 memerlukan provisioning akun oleh Owner/Staff sesuai role, onboarding lewat email, serta deaktivasi tanpa memberikan Staff hak admin provider. M06-AUTH-01 memerlukan Owner memulai perubahan email akun target, alamat baru dikonfirmasi sebelum `AppUser.emailNormalized` berubah, `authSubject` tetap, serta retry/reconciliation dan audit. Kontrak ini ada di M05 Data API §4.1, FSD §7, dan WF-09 SK-31/SK-59. Neon Auth managed tidak memenuhi operasi runtime tersebut; setelah spike, Owner menyetujui migrasi aplikasi ke Better Auth dengan Neon PostgreSQL. Vendor email tetap belum dipilih.

## Keputusan Owner dan batas implementasi

1. Owner mengarahkan penggunaan Better Auth self-hosted dengan Neon PostgreSQL pada 2026-11-03. Pilihan ini mengganti Neon Auth managed untuk runtime aplikasi dan tercatat di ADR-003.
2. Spike `npm run test -- auth-spike` lulus 13/13 pada Neon project disposable; project tersebut telah dihapus. Cakupan yang lulus meliputi invitation-only, batas peran, aktivasi tanpa password sementara, deaktivasi/pencabutan sesi, dan verifikasi email dasar.
3. Gap yang tersisa: endpoint `changeEmail` bawaan hanya mengubah user pada sesi aktif, bukan akun Tenant yang dipilih Owner. M06-AUTH-01 harus memverifikasi alamat baru sebelum memperbarui Better Auth dan `AppUser.emailNormalized`.
4. Aktivasi, reset, dan verifikasi email memerlukan pengiriman dari aplikasi. Better Auth menerima adapter email; vendor layanan email belum dipilih. Tes M06 memakai fake sender; uji pengiriman live di M07 tetap tunduk pada batas tanpa upgrade berbayar.
5. M06-AUTH-05 mengganti adapter runtime, schema Prisma, typed environment, `.env.example`, dan runbook. Verify hanya pada database disposable. Tidak mengubah `.env.local`, akun nyata, branch aktif, deployment, atau konfigurasi Neon Auth aktif.
6. M06-BE-18 dan M06-AUTH-01 berjalan setelah M06-AUTH-05; audit final BE-13 dan dashboard BE-15 tetap mengikuti dependency di TODO.
